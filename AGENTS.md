# Коллекция сайтов — правила проекта

Личный статический каталог понравившихся сайтов: поиск по параметрам, чемпионат по 30 критериям,
отдельная страница на каждый сайт. Всё открывается двойным кликом по `index.html` — без сервера,
сборщиков и npm-зависимостей; Node нужен только чтобы пересобрать страницы после правки данных.

Канонический путь проекта: `C:\Sites\WebsiteCol` (до переезда был `C:\Harness\projects\Коллекция сайтов`).
В коде и данных абсолютных путей нет — все инструменты вычисляют корень от своего расположения,
поэтому папку можно переносить куда угодно.

## Карта

```
index.html, champ.html, categories.html   ГЕНЕРИРУЮТСЯ — руками не правим
pages/NNN-slug.html                       ГЕНЕРИРУЕТСЯ, по странице на сайт
Screens/NNN.webp|png                      скриншоты от владельца; имя = слот
data/sites.json                           ИСТОЧНИК ПРАВДЫ: сайты и их параметры
data/champ.json                           баллы чемпионата: 30 критериев на сайт
data/taxonomy.json                        справочники: категории, аудитории, стили, приёмы, языки
data/weights.json                         профили весов и список критериев
data/palette.json                         палитры, измеренные из скриншотов (генерируется)
data/SCHEMA.md                            описание всех полей данных
assets/style.css, assets/app.js           оформление и логика каталога (правятся руками)
tools/*.mjs                               сборка, проверки, замеры
README.md                                 описание проекта для человека
STATE.md                                  снимок состояния и открытые вопросы
SESSIONS.md                               роли сессий по уровню усилий
MIGRATION.md                              как переносили проект и как проверить после переезда
RESEARCH_PROMPT.md                        шаблон задания на разбор нового сайта
```

## Инварианты (нарушение = потеря работы)

1. **`data/*.json` — единственный источник правды.** Правки только там; страницы пересобираются.
2. **Страницы и три корневых HTML не редактируем руками** — `build.mjs` их перезапишет.
3. **Слот уникален**, `screenshot` совпадает с именем файла в `Screens/` (`"027"` → `Screens/027.webp`).
4. **Ключи в `champ.json` совпадают со слотами в `sites.json`** — иначе `validate` даёт ошибку.
5. **Все id (категории, стили, приёмы, аудитории, языки) существуют в `taxonomy.json`.** Нужного нет —
   сначала добавь в справочник, потом используй.
6. **`palette.json` не правим руками** — он генерируется `tools/palette.mjs`.
7. **Никаких выдуманных данных.** Не измерили — `null`, на странице это «не измерено».

## Команды

| Команда | Что делает | Пишет на диск |
|---|---|---|
| `node tools/build.mjs [--quiet]` | `data/*.json` → страницы | да: 3 HTML + `pages/` |
| `node tools/validate.mjs [--quiet]` | проверки данных, разметки, доступности, контраста | нет (только отчёт, код 1 при ошибках) |
| `node tools/doctor.mjs` | самопроверка окружения: Node, Chrome, память, полнота файлов | нет |
| `node tools/palette.mjs [--dry-run]` | палитры и размеры скриншотов через Chrome | да: `data/palette.json`, `.tmp/` |
| `node tools/check-widths.mjs 1280,1440,1920` | горизонтальное переполнение на ширинах | да: `.tmp/widths.html` |
| `node tools/add-site.mjs <url> --slot 027 --name "Имя"` | черновик записи в `sites.json` | да: `data/sites.json` |

Порядок работы: правим `data/` → `build` → `validate` до нуля ошибок → `palette`, если добавились
скриншоты → `check-widths` перед сдачей. **Read-only сессия может запускать только `validate` и `doctor`.**

## Ритуал добавления сайта

1. **Проверить скриншот**: владелец кладёт файл в `Screens/`, имя — следующий свободный номер.
   Скриншоты снимает владелец; автоматическая съёмка не делается.
2. **Разбор в фоне**: по одному фоновому субагенту на сайт, задание — по шаблону `RESEARCH_PROMPT.md`.
   Агент отдаёт один JSON с фактами и обязательным списком `unverified`. Библиотек не выдумывать:
   подстроки вроде `rive` (из «driven»), `THREE` (из «three-digit»), `d3` (из base64) — ложные срабатывания.
3. **Запись в `data/sites.json`** — поля по `data/SCHEMA.md`; `description_user` — дословно от владельца,
   `description_own` — своё описание, `unverified` — из отчёта.
4. **Оценки в `data/champ.json`** — все 30 критериев, шкала 1–10 шагом 0.5, плюс `section_notes`
   на каждый из восьми разделов.
5. `node tools/build.mjs` — пересборка.
6. `node tools/validate.mjs` — до нуля ошибок и предупреждений.
7. `node tools/palette.mjs` — **только если свободной памяти ≥ 4 ГБ** (см. ниже).
8. `node tools/check-widths.mjs 1280,1440,1920` и уборка: удалить `.tmp/` и временные папки разбора
   в `%TEMP%\<site>\`.

Партия из пяти сайтов проходится целиком за один проход: пять разборов фоном параллельно, затем
пять записей, пять наборов оценок, одна пересборка, одна проверка ширин.

## Чемпионат: правила оценок

- **30 критериев = 30 номинаций.** Разделы (юзабилити, дизайн, контент, техника, интерактив, доверие,
  инновации, соответствие) — только группировка, а не номинации.
- **Владелец не оценивает ничего.** Все баллы — экспертная оценка агента, обоснованная фактами из карточки.
- Шкала **1–10, шаг 0.5**; ключ критерия — `раздел.id` из `data/weights.json`.
- **Вес критерия = вес раздела ÷ число критериев в разделе.** Вес раздела зависит от профиля
  (`shop`, `media`, `portfolio`, `service`, `showcase`); профиль берётся по первой категории сайта
  (`weights.nomination_profiles.by_category`), при необходимости переопределяется полем `champ.profile`
  в записи сайта.
- **Итог = Σ(вес × балл) ÷ Σ весов × 10** → 0–100.
- **Места считаются по баллу критерия напрямую**: равные баллы дают равные места, первое место —
  победа в номинации и засчитывается каждому, кто его разделил. Для ничьих в общем зачёте порядок
  вывода — по числу побед, затем по призовым местам.
- Оценка ставится **по проверяемым признакам**: вес страницы, наличие h1, sitemap, юридического блока,
  поведение при `prefers-reduced-motion`, консольные ошибки и т. п. «Нравится / не нравится» — не аргумент.

## Честность данных

- Не подтверждено — `null` → на странице `<span class="placeholder">не измерено</span>`.
- У каждой записи обязателен список `unverified` — что именно проверить не удалось и почему.
- Различать **измеренное** (палитра пипеткой, widths, размеры файлов) и **прочитанное из кода**
  (анимации, поведение без браузера). В тексте это формулируется прямо: «по коду», «не наблюдалось».
- Расхождение скриншота и живого сайта — фиксировать в `observations` и `unverified`, не сглаживать.
- Если сайт недоступен из этой сети — использовать `translate.goog`-релей и `api.microlink.io`,
  а способ добычи указывать в `unverified`.

## Гигиена ресурсов (важно: машина ронялась от скриншотов)

- **Единица проверки — измерение, а не картинка.** Кадр выше ~2000 px по высоте не снимать.
- Перед браузером: `node "$env:USERPROFILE\.dsh\bin\preflight.mjs"`; **меньше ~4 ГБ свободных —
  браузер не запускать** (скрипты сами откажутся ниже 3500 МБ).
- **Один запуск Chrome на задачу**, всегда со своим `--user-data-dir` (иначе Chrome подхватит
  открытый браузер владельца и проигнорирует флаги). В `tools/` это уже сделано.
- **Не убивать чужие процессы Chrome.** Свои — убивать, проверяя командную строку на `--headless`
  и на свой профиль.
- Временное складывать в `.tmp/` проекта и в `%TEMP%\<site>/`, в конце задачи удалять и то и другое.

## Грабли, уже собранные

- `overflow-x: hidden` на `html/body` **ломает `position: sticky`** — нужен `overflow-x: clip`.
- Ссылка «к списку» на залипающий элемент не работает: браузер считает его уже видимым — цельтесь
  в статичный заголовок выше.
- `app.js` работает и на страницах сайтов, где нет каталога: любые новые обращения к DOM — под guard.
- Палитра в карточке — **из скриншота владельца**, а не из CSS сайта; если расходится с живым сайтом,
  это фиксируется в `palette.source` и `unverified`.
- Правки шаблонов в `build.mjs` проверять `validate`: он ловит порядок заголовков, alt, размеры
  картинок, локальные ссылки, контраст и остатки мобильной вёрстки.

## Роли сессий

Проект ведут четыре сессии с разным уровнем усилий — Max (проектирование, исследование, оценки),
High (рутинное добавление данных), Low (мелкие правки), Off (справка только для чтения).
Что каждой можно и нельзя, какие стартовые промпты — в `SESSIONS.md`.
