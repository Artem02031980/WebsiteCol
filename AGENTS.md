# Коллекция сайтов — правила проекта

Личный статический каталог понравившихся сайтов: главная страница с поиском, фильтрами
и карточками плюс страница-разбор на каждый сайт. Сайт адаптивный (360–1920 px),
светлая тема. Всё открывается двойным кликом по `index.html` — без сервера, сборщиков
и npm-зависимостей; Node нужен только чтобы пересобрать страницы после правки данных.

Канонический путь проекта: `C:\Sites\WebsiteCol`. В коде и данных абсолютных путей нет —
инструменты вычисляют корень от своего расположения, поэтому папку можно переносить.

## Карта

```
index.html                                ГЕНЕРИРУЕТСЯ — руками не правим
pages/NNN-slug.html                       ГЕНЕРИРУЕТСЯ, по странице на сайт
screens/NNN.webp|png                      скриншоты от владельца; имя = слот
data/sites.json                           ИСТОЧНИК ПРАВДЫ: сайты и их параметры
data/taxonomy.json                        справочники: категории, аудитории, стили, приёмы, языки
data/palette.json                         палитры из скриншотов (генерируется)
data/SCHEMA.md                            описание всех полей данных
assets/style.css, assets/app.js           оформление и логика каталога (правятся руками)
assets/fontawesome.css                    локальные иконки Font Awesome (классы .fa*)
assets/fonts/fontawesome/                 OTF-шрифты Font Awesome 5.15.3 Free + лицензия
assets/logo.svg, assets/favicon.svg       логотип (обязателен на каждой странице)
tools/*.mjs                               сборка, проверки, замеры
README.md                                 описание проекта для человека
STATE.md                                  снимок состояния и открытые вопросы
docs/WORKFLOW.md                          пять сессий и шаблон разбора нового сайта
```

## Инварианты (нарушение = потеря работы)

1. **`data/sites.json` — единственный источник правды.** Правки только там; страницы пересобираются.
2. **Сгенерированные HTML не редактируем руками** — `build.mjs` их перезапишет.
3. **Слот уникален**, `screenshot` совпадает с именем файла в `screens/` (`"027"` → `screens/027.webp`).
4. **Все id существуют в `taxonomy.json`.** Нужного нет — сначала добавить в справочник, потом использовать.
5. **`palette.json` не правим руками** — он генерируется `tools/palette.mjs`.
6. **Никаких выдуманных данных.** Не измерили — `null`, на странице это «не указано»/«не измерено»;
   пустые поля так и остаются пустыми, пока их не заполнит другой агент.
7. **Без оценок и рейтингов.** В проекте только каталог и разборы; баллов, номинаций
   и рейтингов нет.

## Требования брифа (дизайн и поведение)

- Фильтры на главной **при загрузке свёрнуты**.
- Сортировка: **«По номеру с конца»** (по умолчанию, свежие сверху), «По номеру», «По названию».
- Значения фильтров — **по алфавиту**; названия, начинающиеся с латиницы, идут **в конце** списка.
  Исключение — «Технологии»: там сначала латиница, потом русский.
- Названия фильтров **не начинаются с символов**: «@react-three/drei» в данных допустимо,
  в фильтрах `build.mjs` сам показывает «React (@react-three/drei)».
- Названия в таксономии — по-русски; если без английских слов не обойтись, они в конце
  названия («Еда и HoReCa»).
- На главной всегда есть фильтр **«Актуальность сайта»**: «Действующий» / «Недействующий».
  Проверки ссылок — **только по прямой команде владельца**; при добавлении сайтов всю
  коллекцию не проверяем.
- Фильтр «Страна» стоит перед «Актуальностью»; значение — страна без города, а пустая
  страна — «Не определено» в конце списка. Между заголовком «Фильтры» и первым фильтром — 28 px.
- Карточка на главной: скриншот, номер, название (ссылка на разбор), описание одной фразой
  (`description_short` или первое предложение), палитра, «Открыть сайт». У недействующих —
  бейдж «Недействующий сайт». Тегов и баллов в карточках нет.
- Вид «Список»: изображение занимает **не меньше половины карточки**; при ширине меньше
  768 px — одна колонка, изображение сверху, текст под ним.
- Страница сайта — **лонг-рид в контейнере 1000 px**: хлебные крошки «Главная / Название»
  прижаты к правому краю; название, теги и ссылка на сайт — по центру; скриншот по ширине
  контейнера (до 1000 px).
  Порядок разделов: «Что это» и «Что смотреть в первую очередь» — два абзаца с заголовками
  в двух равных колонках с зазором 64 px; сразу после них «Приёмы» — четыре равные
  колонки по всей ширине контейнера, маркированный список только с названиями (все приёмы
  сайта из `techniques`); затем «Интересные факты» — нумерованный список в колонке 800 px;
  затем карточки; последним разделом перед feedback — «Технологии»: те же четыре колонки
  и такой же маркированный список названий (доказательства остаются в данных).
  Карточками остаются только «Паспорт» и «Палитра»: стоят рядом, выравниваются по высоте
  большей из карточек, внутренние отступы сверху/снизу 50 px; на узких экранах — друг под
  другом. Вертикальные отступы: 100 px от крошек до названия,
  150 px от ссылки до скрина, 150 px после вводных колонок, 150 px после «Приёмов»,
  150 px после «Интересных фактов», 150 px после карточек, 350 px после «Технологий» до feedback.
  У заголовков «Интересные факты», «Технологии», «Приёмы» и карточек — 35 px до контента;
  на узких экранах межсекционные отступы сжимаются до 48 px.
  Статус на странице — тег «Действующий сайт» (зелёный фон, белый текст) или
  «Недействующий сайт» (красный фон, белый текст).
  Перед футером — постоянная секция feedback с контактами автора коллекции (Артём Хмелёв;
  телефон, почта, Telegram `@artem0203` — все ссылки действующие: `tel:`, `mailto:`, `t.me`),
  выровненная по ширине контента футера. Футер тёмный, текст белый; линия остаётся светлой.
- Страна и автор в данных — короткие, без пояснений: «Австрия, Вена»,
  «Edoardo Lunardi — частный разработчик».
- **Теги на странице сайта** повторяют фильтры каталога и идут строго в этом порядке:
  Тип сайта, Категория, Подкатегория, Для кого, Визуальный стиль, Тема палитры, Цвет фона,
  Приёмы, Технологии, Язык сайта, Страна; тег статуса («Действующий сайт» / «Недействующий
  сайт») — последним и своим цветом. Формулировки: тема — «Светлая тема», «Тёмная тема»,
  «Цветная тема», «Контрастная тема»; цвет фона — «Жёлтый фон», «Нейтральный фон»;
  язык — «Английский язык», у мультиязычных один тег «Мультиязычный сайт»; страна — без
  города (как в фильтре). У каждой группы свой оттенок из **голубой палитры** — от почти
  белого до глубокого синего, без чистых `#000` и `#fff`. Оттенки **перемешаны нарочно**:
  цвет закреплён за группой, а соседние в строке группы контрастны, чтобы палитра не
  выглядела строгим градиентом. Сейчас: «Тип сайта» — `#16324F`, «Категория» — `#C9DCF0`,
  «Подкатегория» — `#2C5282`, «Для кого» — `#DCE9F7`, «Стиль» — `#1F5AA0` (текст белый),
  «Приёмы» — `#A8C4E4`, «Технологии» — `#35618F`, «Язык сайта» — `#46719F` (текст белый),
  «Страна» — `#24466F`. Цвета живут токенами `--tag-<группа>-bg/fg` в `assets/style.css`,
  пары проверяет `validate` (≥ 4,5:1).
  Перекрасить группу — это правка только её пары токенов: порядок, разметку и подписи
  трогать не нужно; оттенки должны оставаться различимыми и не повторяться.
  **Три группы красятся по значению, а не по группе:**
  «Тема палитры» — «Светлая тема» светло-серая `#E6E6E3` с тёмным текстом, «Тёмная тема» —
  чёрная `#111111` с белым текстом («Контрастная тема» — так же), «Цветная тема» —
  фиолетовый градиент `#4C1D95` → `#6D28D9` с жёлтым текстом `#FFE066`;
  «Цвет фона» — чип красится в тот цвет, который называет: красный, оранжевый, жёлтый,
  зелёный, синий, фиолетовый (пастельные заливки), а «Нейтральный фон» — светло-серый
  `#E6E6E3`; «Язык сайта» — синий `#46719F` с белым текстом, чтобы белый шрифт проходил
  контраст, у «Стиля» синий `#1F5AA0` с белым текстом.
  Теги переносятся по строкам с одинаковым зазором по горизонтали и вертикали (0,4 rem),
  строка центрирована. Отдельных полей в данных нет: теги собирает `build.mjs` из
  `site_type`, `categories`, `subcategories`, `audience`, `styles`, `techniques`, `tech`,
  `palette` (режим и цвет фона из `palette.json`), `facts.languages`, `facts.country`.
- Мультиязычные сайты: `facts.languages` — массив, включающий `multi` и конкретные языки
  (`["multi", "fr", "en"]`).
- **Скруглений нет.** `border-radius` в CSS и атрибут `rx` в SVG запрещены — все углы прямые.
  Новых скруглений не добавлять: кнопки, карточки, панели, чипы, бейджи, поля и логотип
  остаются квадратными.
- **Font Awesome — локально.** `assets/fontawesome.css` и OTF-файлы в `assets/fonts/fontawesome/`
  (Font Awesome Free 5.15.3, шрифты SIL OFL 1.1). Внешние CDN и сетевые подключения шрифтов
  запрещены. Иконки: `<i class="fas fa-heart" aria-hidden="true"></i>`; для обычных —
  `.far`, для брендов — `.fab`.

## Команды

| Команда | Что делает | Пишет на диск |
|---|---|---|
| `node tools/build.mjs [--quiet]` | `data/*.json` → страницы | да: `index.html` + `pages/` |
| `node tools/validate.mjs [--quiet]` | проверки данных, разметки, доступности, контраста | нет (только отчёт, код 1 при ошибках) |
| `node tools/doctor.mjs` | самопроверка окружения: Node, Chrome, память, полнота файлов | нет |
| `node tools/palette.mjs [--dry-run]` | палитры и размеры скриншотов через Chrome | да: `data/palette.json`, `.tmp/` |
| `node tools/check-widths.mjs 360,768,1024,1280,1440,1920` | горизонтальное переполнение на ширинах | да: `.tmp/widths.html` |
| `node tools/add-site.mjs <url> --slot 032 --name "Имя"` | черновик записи в `sites.json` | да: `data/sites.json` |

Порядок работы: правим `data/` → `build` → `validate` до нуля ошибок и предупреждений →
`palette`, если добавились скриншоты → `check-widths` перед сдачей.
**Read-only сессия может запускать только `validate` и `doctor`.**

## Ритуал добавления сайта

1. **Скриншот**: владелец кладёт файл в `screens/`, имя — следующий свободный номер.
   Автоматическая съёмка не делается.
2. **Разбор в фоне**: по одному фоновому субагенту на сайт, задание — по шаблону
   `docs/WORKFLOW.md`, раздел «Шаблон разбора нового сайта». Агент отдаёт один JSON с фактами.
   Библиотек не выдумывать: подстроки вроде `rive` (из «driven»), `THREE` (из «three-digit»),
   `d3` (из base64) — ложные срабатывания.
3. **Запись в `data/sites.json`** — поля по `data/SCHEMA.md`; `description_user` — дословно
   от владельца, `description_own` — свой абзац человеческим языком, `description_short` —
   одна фраза для карточек; страна и автор короткие, без пояснений; `link_state` — по факту
   проверки URL нового сайта (всю коллекцию не проверяем). Оценок нет.
4. `node tools/build.mjs` — пересборка.
5. `node tools/validate.mjs` — до нуля ошибок и предупреждений.
6. `node tools/palette.mjs` — **только если свободной памяти ≥ 4 ГБ** (см. ниже).
7. `node tools/check-widths.mjs` и уборка: удалить `.tmp/` и временные папки разбора
   в `%TEMP%\<site>\`.
8. Коммит партии и `git push origin main` — сообщение по-русски в повелительном наклонении
   (см. «Git и GitHub»).

Партия из нескольких сайтов проходится целиком за один проход: разборы фоном параллельно,
затем записи, одна пересборка, одна проверка ширин.

## Честность данных

- Не подтверждено — `null` → на странице `<span class="placeholder">не указано</span>`.
- **Писать для человека с поверхностным знанием IT.** Термины объяснять при первом упоминании
  или заменять понятным описанием; смысл, числа и оговорки при этом не менять.
- Различать **измеренное** (палитра пипеткой, widths, размеры файлов) и **прочитанное из кода**
  (анимации, поведение без браузера). В тексте это формулируется прямо: «по коду», «не наблюдалось».
- **Про скриншот в `observations` не пишут.** Совпадает снимок владельца с живой версией или
  отстал от неё — для фактов о сайте это неважно, а для читателя неинтересно. Устаревший
  скриншот — повод заменить файл в `screens/`, а не пункт в списке «Интересные факты».
- Если сайт недоступен из этой сети — использовать `translate.goog`-релей и `api.microlink.io`,
  а способ добычи указывать в `observations`.

## Гигиена ресурсов (важно: машина ронялась от скриншотов)

- **Единица проверки — измерение, а не картинка.** Кадр выше ~2000 px по высоте не снимать.
- Перед браузером: `node "$env:USERPROFILE\.dsh\bin\preflight.mjs"`; **меньше ~4 ГБ свободных —
  браузер не запускать** (скрипты сами откажутся ниже 3500 МБ).
- **Один запуск Chrome на задачу**, всегда со своим `--user-data-dir` (иначе Chrome подхватит
  открытый браузер владельца и проигнорирует флаги). В `tools/` это уже сделано.
- **Не убивать чужие процессы Chrome.** Свои — убивать, проверяя командную строку на `--headless`
  и на свой профиль.
- Временное складывать в `.tmp/` проекта и в `%TEMP%\<site>/`, в конце задачи удалять и то и другое.

## Грабли, уже собранные

- `overflow-x: hidden` на `html/body` **ломает `position: sticky`** — нужен `overflow-x: clip`.
- `app.js` работает и на страницах сайтов, где нет каталога: любые новые обращения к DOM — под guard.
- Палитра в карточке — **из скриншота владельца**, а не из CSS сайта; в `observations` это
  расхождение не описывается (см. «Честность данных»).
- Правки шаблонов в `build.mjs` проверять `validate`: он ловит h1 и уровни заголовков, alt
  и размеры картинок, локальные ссылки, контраст, skip-link и отсутствие логотипа.
- Headless Chrome может не загрузить CSS живого сайта (computed покажет Times New Roman):
  типографику живого сайта проверяйте по скачанным CSS-файлам, а не только по computed.
- Названия фильтров «Технологии» с латиницей внутри («…стороннем CDN») считаются русскими,
  если начинаются с кириллицы — классификация по первой букве, так задумано.

## Роли сессий

Пять сессий: **ProMax** — структурные изменения самого сайта-коллекции (`tools/*`, `assets/*`,
шаблоны, раскладка, схема данных); **Max** — исследование и содержание сайтов; **High** —
рутинное заполнение данных и партии; **Low** — мелкие правки; **Off** — справка только
для чтения. Подробные границы и стартовые промпты — в `docs/WORKFLOW.md`.

## Git и GitHub

Репозиторий: `C:\Sites\WebsiteCol`, remote `origin` —
https://github.com/Artem02031980/WebsiteCol.git, ветка `main`. `.gitignore` игнорирует `.tmp/`.
Перед началом работы — `git status` и `git pull --ff-only` (при чистом рабочем дереве).
После каждой законченной партии — коммит и `git push origin main`; GitHub считается
каноническим remote, локальный и удалённый `main` должны совпадать.

Коммит — сообщение по-русски, в повелительном наклонении. В одном коммите — одна задача;
чужие незакоммиченные правки не откатывать и не подмешивать. Секреты и токены не коммитить;
force-push в `main` не использовать.
