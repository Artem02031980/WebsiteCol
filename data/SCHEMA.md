# Схема данных коллекции

Единственный источник правды — `data/sites.json` (сайты). Справочники значений — `data/taxonomy.json`,
палитры, измеренные из скриншотов, — `data/palette.json` (генерируется, руками не правится).
Страницы (`index.html`, `pages/*.html`) **генерируются** из данных: `node tools/build.mjs`.
Руками их править бессмысленно — перезапишутся.

Главное правило: **не выдумывать**. Чего не измерили и не видели — `null`, в интерфейсе это
показывается как «не указано» / «не измерено». Поля, для которых данных нет, можно оставить
пустыми — страница честно покажет заглушку.

## Запись сайта (`sites.json` → `sites[]`)

| Поле | Тип | Что это | Обязательное |
|---|---|---|---|
| `slot` | string | Номер вида `"001"` — совпадает с именем скрина в `screens/` | да |
| `slug` | string | Латиница, kebab-case — попадает в имя страницы `pages/001-weeksync.html` | да |
| `name` | string | Название сайта | да |
| `url` | string | Точный адрес, который открываем | да |
| `domain` | string | Домен без www | да |
| `screenshot` | string \| null | Имя файла в `screens/`, например `"001.webp"`. `null` — скрин ещё не прислан | да |
| `added` | string \| null | Дата добавления `YYYY-MM-DD`; на странице показывается как ДД.ММ.ГГГГ | нет |
| `link_state` | string | id из `taxonomy.link_states` | да |
| `description_user` | string \| null | Описание от владельца коллекции, дословно | нет |
| `description_own` | string | Что это за сайт — один абзац, понятным человеческим языком, без углубления в детали. На странице объединяется с `description_user` в единый текст | да |
| `description_short` | string | Одна короткая фраза для карточки: без точки в конце, до 90 символов | да |
| `categories` | string[] | id категорий, первая — основная | да |
| `subcategories` | string[] | id подкатегорий из выбранных категорий | нет |
| `audience` | string[] | id из `taxonomy.audiences` — «для кого» | да |
| `site_type` | string | id из `taxonomy.site_types` | да |
| `styles` | string[] | id из `taxonomy.styles` | да |
| `techniques` | string[] | id из `taxonomy.techniques` — то, ради чего сайт сохранён (в фильтрах, но не в паспорте) | да |
| `palette` | object | `{ "mode": "light\|dark\|contrast\|colorful", "colors": ["#RRGGBB"] }` | да |
| `tech` | array | `[{ "name": "Next.js", "evidence": "файл /_next/static/…" }]` — без доказательства не пишем. Имена пакетов можно писать как есть (`@react-three/drei`): в фильтрах build.mjs сам преобразует их к виду «React (@react-three/drei)». Версии и хвостовые уточнения в фильтре схлопываются: «Astro v6.1.6» и «Astro» — один пункт, на странице название остаётся полным. `evidence` хранится в данных для проверки, но на странице выводится только `name` | нет |
| `observations` | string[] | 3–7 наблюдений, чем сайт интересен технически или визуально. Писать простым человеческим языком; термины объяснять при первом упоминании | да |
| `notes` | string | Заметка: что смотреть в этом сайте в первую очередь | да |
| `facts` | object | См. ниже | да |

### `facts`

| Поле | Тип | Что это |
|---|---|---|
| `https` | boolean \| null | Сайт отдаётся по HTTPS |
| `country` | string \| null | Страна и город, без пояснений: «Австрия, Вена» |
| `languages` | string[] | id из `taxonomy.languages`. Мультиязычный сайт попадает и в «Мультиязычный», и в конкретные языки: `["multi", "fr", "en"]` |
| `author` | string \| null | Автор или студия, коротко: «Edoardo Lunardi — частный разработчик» |
| `year` | number \| null | Год запуска/копирайта, если указан |
| `mobile.viewport_meta` | boolean \| null | Есть `<meta name="viewport">` |
| `mobile.overflow_375` | boolean \| null | Горизонтальное переполнение на 375 px (измеряется отдельно) |
| `seo.title` / `seo.title_len` | string / number | `<title>` и его длина |
| `seo.description` / `seo.description_len` | string / number | meta description и его длина |
| `seo.og` | boolean \| null | Есть Open Graph |
| `seo.sitemap` / `seo.robots` | string \| null | Что нашлось по адресу, `"не найдено"` если 404 |
| `seo.structured_data` | boolean \| null | Есть JSON-LD / микроразметка |
| `links.checked` | number | Сколько ссылок реально проверено |
| `links.broken` | string[] | Битые адреса |
| `contacts` | string \| null | Какие контакты есть на сайте |
| `legal` | string \| null | Юридическая информация, политика конфиденциальности |
| `analytics` | string[] | Счётчики, найденные в коде |

Актуальность ссылки (`link_state`) проверяется **только по прямой команде владельца**:
при добавлении новых сайтов проверять всю коллекцию не нужно. На главной всегда есть фильтр
«Актуальность сайта»: «Действующий»/«Недействующий»; на странице — тег «Действующий сайт»
или «Недействующий сайт».

## Как добавить сайт

1. Положить скрин в `screens/` с номером = текущий максимум + 1 (`032.webp`). Скриншоты снимает владелец.
2. `node tools/add-site.mjs <url> --slot 032 --name "Название"` — создаст черновик записи.
3. Разбор сайта субагентом по шаблону `docs/WORKFLOW.md` (один агент на сайт).
4. Заполнить поля в `data/sites.json` (таблица выше).
5. `node tools/build.mjs` — пересобрать страницы.
6. `node tools/validate.mjs` — до нуля ошибок и предупреждений.
7. `node tools/palette.mjs` — обновить палитры (нужно ≥ 4 ГБ свободной памяти).
8. `node tools/check-widths.mjs` — убедиться, что переполнения нет на 360–1920 px.

Полный ритуал с пояснениями — в `AGENTS.md`.

## Расширение справочников (`taxonomy.json`)

Id из справочников нельзя выдумывать в записи сайта: сначала значение появляется в таксономии,
потом используется. Порядок:

1. Добавить объект `{ "id": "kebab-case", "title": "Как это видит человек" }` в нужный список:
   `categories` (с подсписком `subs`), `audiences`, `site_types`, `styles`, `techniques`,
   `languages`, `palette_modes`, `link_states`.
2. Названия — по-русски; если без английских слов не обойтись, они идут в конце названия
   («Еда и HoReCa»). Сортировку по алфавиту делает `build.mjs` при сборке.
3. `node tools/validate.mjs` — он ругается на неизвестные id, поэтому после правки справочника
   проверка должна проходить.
4. `node tools/build.mjs` — фильтры каталога подхватят новое значение сами.

## Соглашения, накопившиеся по ходу

- `palette.colors` — цвета **со скриншота** (измеряет `tools/palette.mjs`). Если снимок сделан
  на другой теме, чем открывается сайт, это замечание пишется в `observations`.
- `facts.links.broken` — только реально проверенные адреса; «не удалось проверить» туда не пишется.
- Расхождение скриншота с живым сайтом — отдельный пункт в `observations`.
- Дата в `added` — день, когда сайт попал в коллекцию; `null`, если не фиксировали.
- Проверить всё разом после правок: `node tools/doctor.mjs` (целостность и окружение) →
  `node tools/validate.mjs` (данные и разметка).
