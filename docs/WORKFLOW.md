# Рабочий процесс: пять сессий и разбор новых сайтов

Это единственный операционный документ проекта. Правила, инварианты и команды — в
[`AGENTS.md`](../AGENTS.md), поля данных — в [`data/SCHEMA.md`](../data/SCHEMA.md),
текущее состояние — в [`STATE.md`](../STATE.md).

## Пять сессий

Проект ведут пять сессий DSH с разным уровнем усилий. Разделение — по типу работы:
структура сайта, содержание коллекции, рутинные данные, мелкие правки и справка.
Все работают в одном workspace — `C:\Sites\WebsiteCol`.

### 1. ProMax — структурные изменения сайта-коллекции

**Модель:** DeepSeek Pro V4, effort Max.

**Чем занята:** архитектура и устройство самого сайта: `tools/build.mjs`, `assets/style.css`,
`assets/app.js`, шаблоны страниц, навигация и раскладка, адаптивность, состав блоков,
схема данных `data/SCHEMA.md`, инструменты сборки и проверок. Меняет то, как устроен каталог,
а не то, что написано в карточках.

**Можно:**
- менять `tools/*.mjs`, `assets/*`, шаблоны и структуру генерируемых страниц;
- менять схему данных и правила валидации (с обновлением `data/SCHEMA.md`);
- запускать `build`, `validate`, `palette`, `check-widths`, браузерные замеры;
- заводить и переписывать документы проекта.

**Нельзя:**
- переписывать содержание сайтов «заодно» — это Max/High;
- оставлять после структурной правки грязную сборку: `build` + `validate` + `check-widths`;
- коммитить чужие незакоммиченные изменения.

**Стартовый промпт:**

```
Ты ProMax — сессия структурных изменений сайта-коллекции (C:\Sites\WebsiteCol).
Прочитай AGENTS.md, README.md, STATE.md и docs/WORKFLOW.md. Задача: <что меняем в устройстве сайта>.
Работай по правилам AGENTS.md: данные — в data/*.json, сгенерированные HTML руками не правь.
В конце — build + validate до нуля ошибок и предупреждений, check-widths на 360–1920,
обнови STATE.md и закоммить одну законченную задачу.
```

### 2. Max — исследование и содержание коллекции

**Чем занята:** новые сайты, их разбор и текст: `description_own`, `description_short`,
`observations`, `notes`, `facts`, `tech` с доказательствами, `palette`; решения о том,
что именно писать о сайте. Следит за честностью данных и полнотой карточки.

**Можно:**
- исследовать новые сайты, запускать субагентов по шаблону ниже;
- писать записи в `data/sites.json`, содержательные значения в `data/taxonomy.json`;
- запускать `build`, `validate`, `palette`, `check-widths`;
- готовить ТЗ на структурные правки для ProMax.

**Нельзя:**
- менять шаблоны, `assets/*`, `tools/*` и схему данных без ProMax;
- выдумывать факты и заполнять поля «примерно»;
- пересобирать чужие незакоммиченные правки.

**Стартовый промпт:**

```
Ты Max — сессия исследования и содержания коллекции (C:\Sites\WebsiteCol).
Прочитай AGENTS.md, README.md, STATE.md, data/SCHEMA.md и docs/WORKFLOW.md.
Задача: <какие сайты разбираем>. Разбор — по шаблону из docs/WORKFLOW.md,
запись — в data/sites.json, без выдуманных данных.
В конце — build + validate, обнови STATE.md и закоммить партию.
```

### 3. High — рутинные данные и партии

**Чем занята:** заполнение записей по готовому разбору, перенос фактов в `data/sites.json`,
партии новых сайтов, обновление документации, сборка и проверки.

**Можно:**
- писать данные по `data/SCHEMA.md` и готовому отчёту Max;
- запускать `build`, `validate`, `palette`, `check-widths`;
- править `README.md`, `STATE.md`, добавлять скриншоты в `screens/`.

**Нельзя:**
- менять структуру сайта, шаблоны, схему и `assets/*` — это ProMax;
- придумывать содержание и оценки вместо Max;
- переписывать чужие данные без причины.

**Стартовый промпт:**

```
Ты High — рабочая сессия проекта (C:\Sites\WebsiteCol). Прочитай AGENTS.md, STATE.md,
data/SCHEMA.md, README.md и docs/WORKFLOW.md.
Задача: <партия сайтов / заполнить поля по готовому разбору>.
Порядок — по AGENTS.md, в конце build + validate и обнови STATE.md.
```

### 4. Low — мелкие правки

**Чем занята:** опечатки, формулировки, даты, небольшие правки текста и CSS.

**Можно:** править текст в `data/sites.json`, `assets/style.css`, документы; запускать
`build` и `validate`.

**Нельзя:** добавлять сайты, менять структуру, схему, шаблоны, `tools/` и большие куски
данных; запускать браузерные замеры.

**Стартовый промпт:**

```
Ты Low — сессия мелких правок проекта (C:\Sites\WebsiteCol). Прочитай AGENTS.md.
Правка: <что именно>. После правки — build и validate до нуля ошибок и предупреждений,
покажи diff.
```

### 5. Off — справка (только чтение)

**Чем занята:** ответы по коллекции и данным: сколько сайтов, что в категории, какие
незаполненные поля, как устроена схема.

**Можно:** читать файлы, искать по данным, запускать `node tools/validate.mjs`
и `node tools/doctor.mjs`.

**Нельзя:** запускать `build`, `palette`, `check-widths`, `add-site`, браузер, менять файлы.

**Стартовый промпт:**

```
Ты Off — справочная сессия проекта (C:\Sites\WebsiteCol) в режиме только чтения.
Прочитай STATE.md, AGENTS.md и docs/WORKFLOW.md. Отвечай по data/*.json и страницам,
ссылайся на файлы. Ничего не меняй и не пересобирай. Вопрос: <вопрос>.
```

## Передача работы

| Что | Кто решает | Кто делает |
|---|---|---|
| Структура сайта, шаблоны, CSS/JS, схема | ProMax | ProMax |
| Новые сайты: разбор и содержание | Max | Max |
| Рутинное заполнение данных, партии | Max (разбор) | High |
| Мелкие правки текста и CSS | Low | Low |
| Ответы по данным | Off | — |

Единственная durable-память между сессиями — файлы проекта. После каждой законченной
партии обновляйте `STATE.md`; ничего важного в переписке не оставляйте.

## Заявка на новый сайт

Владелец присылает ссылку и скриншот; слот — следующий свободный номер. Для Max достаточно
такой заявки:

```
Сайт: https://example.com
Слот: 032
Название: Example
Скриншот: screens/032.webp
Слова владельца: <дословно или «нет»>
```

Порядок записи, сборки и проверок — в `AGENTS.md`, раздел «Ритуал добавления сайта».
Там же — единственный список команд. Max отвечает за разбор и текст, High — за рутинный
перенос в данные, ProMax — за устройство страниц.

## Шаблон разбора нового сайта

Один сайт — один фоновый субагент. Ниже текст задания: подставить `{СЛОТ}`, `{НАЗВАНИЕ}`,
`{URL}`, `{ОПИСАНИЕ_ВЛАДЕЛЬЦА}`, `{СКРИНШОТ}` и отправить. Пять сайтов — пять таких
заданий параллельно.

Ключевое: субагент **не оценивает**, он приносит проверяемые факты. Чемпионата в проекте нет —
баллов и номинаций в отчёте не существует.

---

```
Ты исследуешь веб-сайт для каталога-коллекции. Нужны ПРОВЕРЯЕМЫЕ факты, а не догадки.

Сайт: {НАЗВАНИЕ} — {URL}
Контекст от владельца коллекции: «{ОПИСАНИЕ_ВЛАДЕЛЬЦА}»
Скриншот страницы: C:\Sites\WebsiteCol\screens\{СКРИНШОТ} (посмотри его инструментом read_image)

Что сделать:
1. Загрузи главную (web_fetch) и 1–3 внутренние страницы (продукт, тарифы, о проекте, контакты).
   ВАЖНО: если домен недоступен (таймаут, обрыв TLS, 403 Cloudflare), действуй через архив:
   https://archive.org/wayback/available?url=<домен> — затем https://web.archive.org/web/<timestamp>id_/<url>.
   Если архив заблокирован по сети, используй релей
   https://<домен-через-дефисы>.translate.goog/<путь>?_x_tr_sl=auto&_x_tr_tl=es&_x_tr_hl=en
   и https://api.microlink.io/?url=<url>. Способ добычи укажи в observations.
2. Зафиксируй только то, что реально видно: title, meta description, lang, viewport, og-теги, h1,
   структуру секций, robots.txt и sitemap.xml (запроси /robots.txt и /sitemap.xml), HTTPS, контакты,
   юридическую информацию, счётчики аналитики.
3. Определи технологии по признакам в разметке (next/react, nuxt/vue, astro, svelte, webflow, framer,
   tilda, wordpress, gsap, lenis, three.js, lottie, rive, tailwind, CMS, аналитика, хостинг).
   Каждая технология — с коротким доказательством (имя файла, класс, заголовок ответа).
   ОСТОРОЖНО С ЛОЖНЫМИ СРАБАТЫВАНИЯМИ: «rive» внутри «driven», «THREE» внутри «three-digit»,
   «d3» внутри base64, «Howl» внутри «howLine», «react» внутри «reacting». Проверяй контекст.
   Имена пакетов пиши как есть: «@react-three/drei» допустимо — фильтры сами преобразуют.
4. Опиши визуальный стиль и приёмы по скриншоту и разметке: палитра (hex из CSS-токенов),
   анимации, курсор, звук. Если CSS недоступен — не выдумывай, оставь поле пустым.
5. Проверь 5–10 внутренних ссылок на доступность, отметь битые.
6. Если сайт многоязычный — перечисли языки, которые реально есть (сверяясь со справочником
   data/taxonomy.json → languages: en, fr, ru, de, it, ja, multi).

Ресурсная гигиена: браузер запускай максимум один раз и только при реальной необходимости
(свободной памяти меньше ~4 ГБ — не запускать вовсе), кадр не выше 2000 px по высоте,
после себя убивай только свои процессы Chrome. Скачанное складывай в %TEMP%\<слаг>\,
в папку проекта ничего не пиши.

Жёсткое правило: не выдумывать. Не видно — null. Качество не оценивай.

Формат ответа: один JSON-объект в блоке ```json, поля:
{
  "slot": "{СЛОТ}", "name": "{НАЗВАНИЕ}", "url": "{URL}", "domain": "<домен без www>",
  "http_status": "...", "https": true, "link_state": "alive",
  "title": "...", "title_len": 0, "meta_description": "...", "meta_description_len": 0,
  "lang": "...", "viewport_meta": true, "h1": ["..."],
  "og": {"present": true, "title": "...", "image": "..."}, "structured_data": false,
  "robots_txt": "...", "sitemap_xml": "...",
  "footer_contacts": "...", "legal_info": "...", "analytics": ["..."],
  "tech_stack": [{"name": "...", "evidence": "..."}],
  "sections_on_page": ["..."],
  "country_hint": "коротко: «Австрия, Вена» — без пояснений, либо null",
  "author_or_studio": "коротко: «Edoardo Lunardi — частный разработчик», либо null",
  "year_hint": 2024,
  "style_notes": "...", "palette_hex": ["#..."],
  "languages": ["en"],
  "techniques_seen": ["..."],
  "broken_links": ["..."], "checked_links_count": 0,
  "short_description_ru": "абзац человеческим языком: что это за сайт, без углубления в детали",
  "description_short_ru": "одна короткая фраза без точки в конце, до 90 символов",
  "notable": ["3–7 наблюдений, чем сайт интересен технически или визуально"],
  "what_to_see_first": "одна-две фразы: что смотреть в первую очередь"

```

`link_state` — id из `data/taxonomy.json → link_states`: `alive`, `moved`, `dead`, `unknown`.
Для нового сайта ставь по фактическому ответу его URL; полную проверку коллекции не запускай.

## Что делать с ответом

1. Запись в `data/sites.json` по `data/SCHEMA.md`: `description_user` — дословно от владельца,
   `description_own` — из `short_description_ru`, `description_short` — из `description_short_ru`,
   `observations` — из `notable`, `notes` — из `what_to_see_first`, `facts.languages` — из `languages`,
   `facts.country` / `facts.author` — короткие значения без пояснений,
   `link_state` — из ответа. Оценок нет. Поля без данных оставить пустыми (null) —
   их заполнит другой агент.
2. Дальше — по ритуалу из `AGENTS.md`: сборка, проверки, палитра при новых скриншотах,
   `STATE.md` и коммит.
3. Удалить `%TEMP%\<слаг>\` и `.tmp/`.

## Замечания, собранные на практике

- Если сайт блокирует сеть (Cloudflare 403), это **свойство доступа**, а не сайта: помечай способ
  добычи данных в `observations` и не переноси в факты то, что не прочитано.
- Скриншот владельца может фиксировать **более раннюю версию** сайта — сверяй текст с живой
  разметкой и расхождения пиши в `observations`.
- Двуязычные сайты: в `languages` — `multi` плюс конкретные языки, например `["multi", "fr", "en"]`.
- Тяжёлые сайты (Unity WebGL, гауссовы сплаты) описывай по файлам сборки и загрузчику, но не
  утверждай, что видел сцену.
